# Conversation history: source contract and native ownership

Source audit, October 7, 2026. These findings come from active C# and an offline decode of the original prefab. No original-game session or new visual qualification was needed to recover the behavior below.

## Original behavior

[`NPCTalkHistroy.cs`](../../Assets/Scripts/Chenzhi/NewUI/Scripts/PE_GameUI/NGUIScripts/NPCTalkHistroy.cs), lines 6–83, owns an archived list of speaker names and resolved conversation text. `SaveCount` is 20. `AddHistroy` compares the exact content string against **every retained entry**, irrespective of speaker; a duplicate does nothing. Otherwise it appends and removes the oldest row if the count exceeds 20. `Clear` empties the list. Raw newlines remain part of the stored value and duplicate key.

[`UINPCTalk.cs`](../../Assets/Scripts/Chenzhi/NewUI/Scripts/PE_GameUI/NGUIScripts/UINPCTalk.cs) records resolved page text when assigning/presenting it, including `MatchTalkInfo` (line 990), `Show` (1203), and the next-page path (1645). This is presentation history, not a list of acknowledged or completed missions. Canceling a page does not erase it. `OnMutexBtnClick` (1324–1333) records the selected response under the main player's resolved name after its mission-selection call. Unselected options are not player utterances. `ResetMissionItem` also has a peculiar empty-content-only branch (1667–1671); the model therefore permits empty strings, but the native hosts must not invent blank player rows to imitate that branch outside its actual context. Native numbered labels and the synthetic `Continue` action are controls, not dialogue text.

[`NpcTalkHistoryWnd.cs`](../../Assets/Scripts/Chenzhi/NewUI/Scripts/PE_GameUI/NpcTalkHistoryWnd/NpcTalkHistoryWnd.cs), lines 16 and 57–101, formats each entry as a blue `speaker :` line followed by white content. It removes LF characters **for display only**. Entries appear oldest first. Opening, adding and removing rows trigger a table reflow followed by a delayed 0.2-second scroll to the bottom when the scrollbar is active (otherwise zero). Its Clear button destroys displayed rows, resets scroll to zero and clears the model (131–143).

[`UIMinMapCtrl.cs`](../../Assets/Scripts/Chenzhi/NewUI/Scripts/PE_GameUI/GameMain/UIMinMapCtrl.cs), lines 863–868, toggles the history window from its minimap control. No dedicated keyboard binding was found in the inspected history window, minimap or GameUI paths. [`GameUI.cs`](../../Assets/Scripts/Chenzhi/NewUI/Scripts/GameUISystem/GameUI.cs), lines 451–468, installs the history prefab under the central UI root and resets its local position.

History is an `ArchivableSingleton` with `GetYird() == false`: its archive is global to the game rather than owned by an individual world. It writes version 1, row count and .NET name/content strings. [`ArchivableSingleton.cs`](../../Assets/GameArchive/ArchivableSingleton.cs) registers it with the archive; [`PeGameLoader.cs`](../../Assets/PeLauncher/PeGameLoader.cs), lines 1404–1416, calls its New/Restore path. The base `New()` is empty and the history class does not override it; do not claim an explicit source clear-on-New call. A fresh singleton starts with an empty list. The native new-session reset below is an explicit lifecycle choice.

## C model and save contract

[`pe_conversation_history`](../../rebuild/src/pe_conversation_history.h) is the graphics-independent owner. Both hosts supply already-resolved visible text and selected responses. The model preserves source FIFO retention and content-only deduplication. It validates UTF-8 and rejects oversized input without truncation or mutation: speaker capacity 128 bytes, content capacity 4096 bytes, each including NUL. These finite limits are native adapters; source .NET strings are unbounded. Active duplicate content, unterminated/invalid UTF-8, nonzero tails after NUL and nonzero unused rows are invalid. Failed add calls preserve both the model and the optional `added` output. Inputs may alias retained entries across eviction.

`PeGame.conversation_history` is retained across menu return, clone, move and successful world replacement. New games start empty; destruction clears it. The tutorial's host-owned instance uses the same model/view but is transient. Neither renderer may mutate history. Presentation hooks must retain the currently presented identity when Clear is pressed so the unchanged page is not immediately recorded again on the next display frame. Capture the actual formatted text shared with dialogue rendering, not raw placeholder strings or decorated choice labels. Existing mission/reward timing remains unchanged, including the user-selected final medicine acknowledgment.

PECSv21 preserves the literal v20 payload, then appends **84,484 bytes**: a little-endian u32 row count followed by twenty stable-order records, each 128 raw speaker bytes and 4096 raw content bytes. There is no pointer, C padding, UI scroll position or window-open state in the wire record. All unused bytes are zero. Versions 1–20 load with empty history; loading does not invent earlier conversations. V21 validates the complete record before committing. Failed load, invalid live-state save and clone rejection leave the prior game/file intact. Save capacity includes the complete bounded suffix. The existing hunt inspector delegates to `pe_game_load` and needs no separate version parser.
