# Hare melee contact and authoritative HP

`pe_hare_damage.[ch]` is an implemented, headless contact resolver for the five recovered hare melee attacks. It connects the existing `pe_hare_attack` clock and guide deduplication with authored hare forearm capsules, a supplied target's authored defence pose, and caller-owned current HP. It does not select enemies, run a retaliation behaviour tree, schedule skill guides or integrate the sandbox frontend.

## Source contract

`skMain` skills 30100003, 30100004 and 30100008 use trigger10100; 30100046 uses10400 and 30100047 uses10250. All three trigger rows require `colinfo` and share the same numeric HP expression: `A*A/(D+A)`, multiplied by the melee shield factor and an already resolved critical factor. `SkExpFuncSet.TryGetHurt` then applies the selected defence part's positive damage multiplier. This is the existing `pe_combat_damage` expression; a second damage formula is not introduced. Source rows were read directly from `Assets/Resources/DataBase/localData.bytes`.

These events also set rigid attribute29 to−1 and carry forces100/400/250; those responses are not implemented here. Trigger10100 passes experience .1 to `TryGetHurt`; triggers10400/10250 instead increment caster raw attribute74 by .1 directly. The identical HP expression does not make their complete side effects identical. The new helper applies none of these XP, rigid or effect57 side effects.

`PEAttackTrigger.CheckHit` iterates attack parts, then defence parts in authored array order. Each successful `PECapsuleTrigger` contact sets distance0; its strict replacement comparison therefore preserves the first overlapping pair. This helper processes **one host-ordered forearm trigger group** per call, preserving PEHB record order inside that group. It does not invent global ordering between the right/left triggers or different targets. Disabled and irrelevant-kind records are skipped; every participating pose must validate before any mutation.

`SkInst._hitInGuide` deduplicates targets within the actual skill guide. Both forearms share that successful-hit list. Attack2 has two guides, so a later valid guide can hit the same target again; Animator window index is not a guide index. The host must provide the currently active guide independently. `SkInst.cs:361–393` disables external collision execution during pre-time, clears the successful-hit list after pre-time, enables it during main-time, then disables it before post-time. Its `GuideCnt` is one-based, whereas this resolver uses zero-based guide indices. Attack2 database pre-times .36/.24 and main-times .15/.24 do not alone fix observed contact timing: source waits are skippable and EX Animator end events are separate signals. The helper first checks the existing action clock's open normalized window and selected forearm group, and uses the matching nonlooping `attack0`…`attack4` clip at `normalized_time * source_clip_duration`. A forged/stale open-window bit cannot open contact outside the authored clock interval. A mismatched/missing clip or duration fails closed.

Host eligibility must include a living attacker, runnable/current collision-enabled skill, active defence trigger, target restriction, source layer filters, reputation permission, faction conflict and DamageID permission. `m_HitTriggers`/`m_EffectedTriggers` dispatch bookkeeping remains outside this helper and is distinct from successful guide dedupe. Nearby geometry alone never authorizes damage. Source BTMelee's branch probability, initial/own/shared cooldowns, HP-range and obstruction gates still belong to their existing action/host boundaries; pounce is not implemented.

## API and ownership

`pe_hare_damage_resolve(action, attack, target, hp, result)` receives a pointer to the host's authoritative current HP. It stores no HP or persistent pointers of its own. On a successful real capsule overlap, the helper prepares the complete numeric result, records the target in a temporary action, then atomically publishes the action, new HP and result. Zero-damage shielded contacts still consume a successful guide contact. Actual HP loss is distinguished from formula damage, and `died` is true only for a positive-to-zero transition. A dead target cannot emit another death transition.

Invalid values, blocked/dead/self/duplicate contacts, full dedupe capacity, closed windows and misses leave action, HP and result unchanged. Hit callbacks, player death handling, hurt animations and persistence remain the host's responsibilities. Callers must render the same hare clip/time and supply the exact evaluated target pose used by their renderer.

The available female defence assets are `rebuild/build/player-defence/player-defence.peac` and `.pehb`, described in [PLAYER_DEFENCE.md](PLAYER_DEFENCE.md). They contain a separate compatible23-joint actor and16 source defence capsules; loading that PEHB against the17-joint rendered torso is invalid. They are not missing merely because they are outside `reference-assets`. Their source-prefab versus installed-bake provenance and transition/IK limitations remain unchanged. Recovered hare geometry is `rebuild/build/reference-assets/hare.peac` and `.pehb`.

## Verification and remaining integration

Optimized strict C11 (`-Wall -Wextra -Wpedantic -Werror`) and ASan/UBSan with leak detection pass, including both recovered-asset checks without skips. The focused C test verifies all five authored attack clocks; first-pair selection; both forearms sharing a guide; attack2's distinct second guide; strict tangency; root/yaw/scale transforms; shield and critical damage; overkill and one-time death; caller-owned HP mutation; eligibility, self/dead/closed-window gates; capacity; and transactional malformed pose/clock/input rejection. Optional asset checks load actual hare attack geometry and the actual auxiliary female defence actor, align a real posed forearm/defence pair as an explicit fixture, and require a successful contact. That constructed overlap validates geometry plumbing, not a measured live hit, timing or range.

Host integration still needs original skill-guide progression, source target/permission selection, shared player HP and death handling, matching rendering clocks, and physical validation. No original-game control, native graphics launch or save-format change was performed for this helper. See [TRAINING_ENEMY.md](TRAINING_ENEMY.md), [HARE_MOVEMENT.md](HARE_MOVEMENT.md), and the separate original/native evidence in [PLAYTEST.md](../PLAYTEST.md).
