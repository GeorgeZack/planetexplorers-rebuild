# Sandbox alignment: implementation work order and live reference

Original audit and reference playtest: 2026-10-03, US/Central. That session changed no C gameplay; its 23:59 stopping deadline was session-specific. An implementation checkpoint dated 2026-10-05 is appended below. The original observations and work-order table remain historical evidence, with the checkpoint identifying which parts are now implemented.

The default sandbox is a separate host from the tutorial. As of October 5 it connects recovered UI and player presentation to real Adventure progression and shared render-derived collision. Its bounded procedural world, population, most actions and wider survival systems still differ substantially from the original. The checkpoint does not claim full Adventure parity.

The first milestone should be one bounded, source-backed survival area with the original start and a complete playable loop. Full procedural-world replication can follow without blocking that milestone. If Single Player Build is selected as the primary target instead, use its stockpiles/known formulas, locked-count policy, frozen world clock and terrain-without-town path in step1; the shared controller, actions, UI and persistence work still applies. Scope bands below describe engineering breadth, not calendar commitments.

## October 5 C implementation checkpoint

This section describes implemented C behavior and separately reported headless validation. It does not add observations of the original executable. The initial headless checkpoint below is followed by the completed integration/playtest update; it does not itself establish original-client parity.

### Real Adventure state and persistence

[PeGame](../../rebuild/src/pe_game.h) now distinguishes `PE_GAME_ADVENTURE` from the explicit older `PE_GAME_LEGACY` prototype. New sandbox sessions use Adventure. The content exporter includes 72 original items and 21 formulas: the exact 13-entry PrototypeItem 1289 starter package, 500 money, the 18-entry quest 9032 supply grant and the required recipe-book closure. Adventure starts with no known formulas. Initial scanner upgrades set separate scanner flags; they do not teach crafting recipes or open an implemented scanner view.

Arrival 9031 completion and 9032 supply acceptance are explicit core actions. Acceptance adds the complete package atomically, refuses insufficient capacity and cannot grant again. Recipe scripts are consumed only when they teach at least one new formula. The existing timed craft transaction, output delivery/cancellation and stable equipment-instance durability remain authoritative. Nine quickslots reference an equipment instance or stack prototype; they are not duplicate inventory stacks. Hand-equipment selection includes recovered supported knife/sword/bow/tool entries, but selecting a weapon does not implement its combat behavior. Headlamp, water pitcher, battery and shield behavior remain outside this slice.

HP starts at 500. Herbal Juice uses the source immediate 30 HP plus bounded timed healing/cooldown behavior; dead-state use is rejected rather than silently reviving. Hunger, comfort, oxygen, shield/energy and general combat/death are not fabricated by the character screen. The inventory still has 32 total owned slots across displayed categories; the source 42-cell panel is presentation geometry, not an expansion to the original full inventory capacity.

[PECS v4](../../rebuild/src/pe_save.c) now stores mode, mission/supply flags, known formulas, scanner state, money, quickslots, HP and juice timing with existing world, equipment, craft and construction state. Versions 1–3 load as the explicit Legacy mode, retaining its unrestricted known-recipe behavior rather than retroactively giving old saves an incomplete Adventure grant. Adventure save-spawn validation uses the actual terrain/Block45/furniture capsule query. These remain C saves, not imports of the original Unity archives. Adventure terrain import preserves possessions and progression.

### Shared geometry and visible player

The new [sandbox collision adapter](../../rebuild/src/pe_sandbox_collision.h) builds terrain collision from the same marching-cubes triangles used for rendering, plus actual Block45 surfaces and existing furniture boxes. It owns its caches outside saved `PeGame`, compares content even when a loaded world reuses a revision number, and replaces a complete collision snapshot only after successful construction. Solid containment complements triangle overlap so a capsule fully embedded inside terrain is rejected. Live edits and loaded worlds refresh collision before movement.

The default host now uses capsule slide/step/support queries through that adapter. This is a replacement controller with .003 m skin, .35 m step and normal Y ≥ .65 walkability, not Unity physics. Source walk/run/sprint speeds 2/5/8, stamina gates/costs and bounded jump-action state are represented; jump impulse 7/gravity 20 remain provisional. Spawn/import recovery searches only vertically, within +4/−5 m, and can fail rather than placing the player inside geometry. Placement still uses conservative player-AABB exclusion and sampled terrain-cell checks; the shared movement mesh does not certify all placement semantics.

[pe_sandbox_actor](../../rebuild/src/pe_sandbox_actor.h) connects the actual recovered female starter appearance and six locomotion clips to measured movement. It supplies the character-window preview without creating another gameplay entity. Matching optional source knife 33 and wood-shovel 12 attachment scenes display supported stowed equipment. Each attachment must match the body clip clocks. This is a fixed appearance, with forward-only discrete clip selection, sprint/run fallback and no complete Animator blending, customization or root-motion system. The renderer does not apply attacks or terrain edits. The default host offers third-person/first-person switching; its camera is still a bounded approximation rather than the full source camera graph.

### Recovered UI and application routing

[pe_sandbox_ui](../../rebuild/src/pe_sandbox_ui.h) reuses source atlas sprites, bitmap fonts, sliced panel borders and recovered UI effects. I opens inventory; C opens character; Q opens missions; Y opens the Replicator. Category-filtered inventory displays actual items/icons and instance wear. Right-click routes use/equip/learn through the core; drag assigns stable quickslots. Original quickbar mouse semantics are preserved: right-click uses and left-drag moves/swaps references. Number keys use shortcuts. The Replicator lists only known formulas, supports text search, scroll, quantity controls, actual ingredient counts, timed jobs and cancellation. Unsupported attributes remain blank rather than displaying tutorial values.

The UI owns input routing before world actions. Modal panels, drags, consumed clicks, quickslot actions and closing frames cannot also mine/build. Inventory chrome blocks obscured quickslots. Pausing freezes simulation; opening an ordinary panel blocks world input while the host continues applicable simulation. The minimap is generated from the actual bounded terrain samples, with the player, placed cells and current supply beacon; it does not show the training-room PNG or tutorial NPC markers. It is a terrain overview, not a port of the original world-rendering minimap.

The current Adventure interaction is deliberately a **provisional supply beacon at local `(32,27)`**. The player approaches it and presses E for Arrival, then E again for supply acceptance. It exercises the audited core state transitions without pretending that generated Eitai/Westina/Annot NPCs, settlement generation or their dialogue are implemented. The tracker directs the player to that working interaction, then to learning/crafting. Mission details retain the source next objective, “Go to Annot,” and explain that settlement travel is not available yet.

The application now has Continue Sandbox, New Sandbox, Tutorial and Quit routes with recovered original logo/fonts. Its background is newly rendered; the original animated planet/menu scene is not ported. Sandbox pause offers resume, save, load and main-menu return. Training pause has matching visible Resume/Main Menu/Quit hit areas, Escape/M/Q shortcuts and a distinct main-menu return result. Both hosts release their graphics resources before returning to the application menu. Continuing an in-memory sandbox preserves its actual state; starting a new one is a separate action.
