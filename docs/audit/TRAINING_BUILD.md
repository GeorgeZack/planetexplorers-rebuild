# Native tutorial construction adapter

`pe_training_build.c/h` is a bounded lesson adapter over the existing source-backed `PeB45Cell` representation. It does not use the sandbox's older one-meter `PeBlock` proxies or create a second resource inventory. The host supplies the authoritative lesson dirt counter, mission/input permissions and player capsule. Mission completion remains the receiver evaluator's responsibility.

## Geometry and transactions

The state holds up to1024 cells, a count and revision. Each cell uses original half-meter coordinates, packed cube/ramp shape and rotation, and material0 (dirt268). The safety extent is cell indices[−256,255], corresponding to world[−128,128]; this is an explicit bounded implementation limit, not a recovered original build restriction. Batches contain1–64 cells. Other materials, extended blocks and other primitives are rejected.

`pe_training_build_add` checks the complete candidate batch before spending dirt: valid cells, duplicates, capacity, revision overflow and actual capsule exclusion. Candidate triangles come from `pe_b45_mesh` and feed `pe_scene_capsule_overlap`; a contained capsule midpoint also rejects a capsule entirely enclosed in a primitive. This permits a capsule near a cube corner or in a ramp's empty half when a box proxy would reject it. The host still controls placement permissions and surrounding-room intersection policy.

Build cost is `ceil(cells/4)` per operation. Removal validates unique indices before refunding `floor(cells/4)`; numeric inventory-capacity failure preserves the complete operation. One four-cell batch costs/refunds1; four individual placements cost4 and individual removals refund0. No fractional credit is accumulated. `pe_training_build_clear` performs source-style task cleanup without refund. Failed operations preserve cells, count, revision and dirt; idempotent empty cleanup preserves revision.

`pe_training_build_mesh` emits world-space triangle-list geometry. `pe_training_build_collision` copies it into an independent BVH, replacing an old snapshot only on success. Rendering and movement should share this geometry and refresh when revision changes. Faces between neighboring cells are not culled. `pe_training_build_raycast` uses actual cube/ramp shape geometry, suitable for checking an obstruction; its underlying existing Block45 helper returns an exit hit for an inside-origin ray. Unity suppresses a collider containing the ray origin, so source receiver evaluation must explicitly exclude those cells where relevant.

## Source point-brush targeting

Source references are `BSPointBrush.cs`, `BSBrush.cs`, `Tools/BSMath.cs`, `BSDataSource.cs` and `BuildingMan.cs` under `Assets/Scripts/WuYiqiu/Building System/Scripts/`.

The original size1 point brush uses camera mouse rays against **voxel data**, not arbitrary room MeshColliders. `BuildingMan.Datas` contains smooth terrain and Block45. Add chooses the nearest datasource; subtract tests Block45 only. Terrain picking treats samples at volume≥128 as unit grid boxes centered on integer source coordinates (datasource offset−.5). Block45 picks occupied half-meter grid boxes, even for ramps; this selection geometry is distinct from their actual physics/rendered shape. A ray starting inside an occupied cell suppresses that datasource.

`pe_training_build_target` provides this bounded size1 behavior and returns both the grid-face hit and snapped half-meter cell. For cube/terrain face cases, the source scaled normal and datasource factor reduce to `floor((worldFace ± unitAxis*.25)*2)` for add/remove. Negative coordinates use floor. No3m player reach or room-collider target is added. Source search is limited by loaded LOD0 bounds capped at half-extents(64,32,64), with a10000 numerical distance ceiling; the native selector instead searches its explicitly bounded supplied terrain/cell state with that ceiling. Exact tied corner hits use deterministic axis priority, rather than reproducing the source's strict-comparison miss. Full diagonal brush offsets, larger patterns, extended-block picking, free-size brush, selection/undo and loaded-world view bounds are outside this size1 adapter.

Default BuildMode is B (`PeInputSettings.cs`). Point brush adds on left click, subtracts on Alt+left click, and rotates on T. Its authored patterns are size³ volumes. The sandbox's V shape toggle and four-cell planar brush are not source point-brush controls.

## Authored anchor terrain

`EmitlineTask.CreatTerrian` writes exactly32 smooth volume255/material1 samples: `(x17..20,y1,z10..13)` and `(x10..13,y2..5,z9)`. These are not preplaced Block45 cells. `pe_training_terrain_build_anchors(world,false)` overlays only those coordinates, and `true` clears the same coordinates without restoring previous values or refunding resources. The existing tutorial-world origin applies; the training-prefab transform does not.

`export_training_terrain.py` now generates both726 mining samples and32 construction anchors from their original source methods. It checks equal create/destroy coordinate sets and zero cleanup values, records both source hashes, and fails if the bounded grammar/schema changes. Run `python3 rebuild/tools/export_training_terrain.py --check` and `python3 rebuild/tests/test_training_terrain_export.py`.

## Fixture drift review

The Makefile registers build, terrain and receiver C modules/tests in core and sanitizer targets, the generated terrain header as a dependency, the terrain generator in `check-content`, and four terrain-export plus three building-asset tests in `test`. Both726 mining and32 construction samples are generated from original create/destroy methods. Receiver rays and boxes remain hand-transcribed native constants. A read-only comparison of the actual compiled50 native rays to the source/installed export manifest found all50 matches; maximum origin discrepancy was5.928×10⁻⁶m. Native rounded receiver bounds differed by at most1.344×10⁻⁶m from the composed source transforms. These tolerances acknowledge serialized quaternion roundoff rather than claiming bit-identical transforms.

The existing receiver unit tests validate scoring,50/49 blockers, misses, malformed callbacks, boxes and triangle rays. Existing asset tests validate source/installed agreement metadata, beam count/directions, collider flags and mesh files, but do not automatically compare native coordinates against the exported manifest. The new `tests/test_training_receiver_source.py` closes this comparison gap: it compiles the actual native receiver module into a temporary shared library, matches each of its50 rays uniquely to the recovered manifest and compares every emitted collider vertex to the transformed source corners. The two tests pass with the exported local assets and explicitly skip if that optional source/installed fixture is unavailable. No generated receiver header is introduced.
