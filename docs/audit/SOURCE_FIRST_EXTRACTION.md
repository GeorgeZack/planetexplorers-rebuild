# Extraction and reference testing

Use source/data for explicit rules and the original engine for genuinely unresolved evaluation. Qualified extraction does not add a Unity dependency to the C runtime.

## Reuse before capture

- Read active C# callers, exact DB rows, XML, prefabs/controllers and preserved saves. Archives often contain realized target, equipment, wallet or generator state already.
- Generic transform animation can be decoded offline; humanoid muscles require Avatar/native evaluation beyond direct TRS channels.
- Prepare the union of missing exact leaves, directions, mounts, hitbox bones and consumers; calculate sample/time/byte budgets before launch. Export all compatible body/attachment/defence views from one qualified hierarchy capture.
- A live pose, isolated leaf, root delta and composed controller pose are different contracts. Never substitute static seeks for sequential root evaluation.

[Isolated leaf bake](ANIMATOR_BAKE.md) creates transform/Animator clones with a verified Avatar, disables events/root application and retains qualified cleanup. Bounds are32 leaves/3600 samples. Do not manually equip every item to recover the same body leaves. Preserve complete source-matched groups and newer installed prefixes.

[Root motion](RUNNING_KNIFE_ROOT_MOTION.md) was qualified with sequential evaluation at two speeds and unchanged5mm cross-rate gate; failed04/05 and passing06 establish why sampling density matters. Reuse qualified curves; do not weaken gates to accept a convenient trial.

## Math, visuals and input

CameraForge graph readers and C# nodes can be decoded before tuning screenshots. Installed managed scalar helpers can be evaluated offline with explicit dt; this does not qualify every camera query or final framing. Source atlases/material constants/UVs are offline facts; native lighting remains an adapter. Input ownership/transactions can be proved headlessly, followed by actual keyboard/pointer/layout checks.

Capture preflight verifies actual equipment/view/action state before arming. Intended input is not proof the game admitted it. Keep contextual sentinels and mutation/schema tests; a driver startup failure is not gameplay evidence. [Runtime diagnostics](../REFERENCE_RUNTIME.md#graphics-diagnostics-and-limits) records bounded successes and failures, not a permanent renderer fix.

## Recording bounds

[Full-pose observer](../../rebuild/tools/REFERENCE_POSE.md): default600 frames/20s, maximum3600/120s or256MiB. Wait1800s is pre-arm, not recording duration. Clean capture-limit means a closed bounded file, not that every requested action occurred; byte-limit error is not qualification. Existing3600-frame Zink run lasted74.37s/226.2MiB;187-frame llvmpipe run119.42s. These are observed cadences, not benchmarks. A30-minute extrapolation at the former density is~5.35GiB, not a supported mode.

The pose observer records evaluated hierarchy/Animator state, not synchronized keys, all action/skill owners, inventory transactions or external IK internals. Specialized hunt/defense probes have their own64/16MiB bounds and120s windows. No automatic rolling/rearm/session recorder exists. New telemetry is a separate bounded tool task.

For broad user feedback, one game-area video plus timestamps can cover movement, camera, combat, UI and save/reload; user remains sole input operator. Use short telemetry bursts only for named missing facts. A half-hour video cannot certify hidden clocks, random distributions, migrations, unseen content or independent-layer phase coverage.

Before a long recording, verify a short file/playback, actual source selection, encoder performance, free space and responsiveness. Installed obs/ffmpeg/gpu-screen-recorder availability alone does not prove those. A proposed720p/30fps H.2646Mbit/s payload is nominal1.35GB/30min before overhead, not a hard cap. No audio is required. Preserve renderer/profile, Player.log, save hashes and actual process outcome.

`reference_input.py` focuses/injects input; it is not a passive video recorder. Native `PE_SANDBOX_PROFILE=1` aggregates stages at120 frames/exit, and `PE_SANDBOX_COMBAT_TRACE=1` bounds4096 changed-hit/kill records; neither is synchronized original telemetry. Record a baseline mode/seed/stats/equipment/mission state, useful action timestamps and end state/new slot, without replaying quests merely to rediscover static data.
