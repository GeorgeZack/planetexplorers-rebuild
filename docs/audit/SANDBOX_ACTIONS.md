# Sandbox shovel, pickaxe and axe action clocks

This October 5 increment separates action timing from inventory/world transactions. `pe_sandbox_actions.c/h` is a headless, transient host for Wood Shovel12, Wood Pickaxe19, Safety Axe1527 and Wood Axe26. It does not depend on `PeTraining`, its grants, scripted seven-hit tree, mound, or mission completion. The complete headless core suite, including the new action tests, passed optimized and ASan/UBSan/leak runs; the12 content tests and source regeneration check passed. Earlier shovel/axe frontend integration and bounded physical-input tests passed; see [playtest evidence](../PLAYTEST.md). The item19 extension now passes the complete optimized core and ASan/UBSan/leak suites, twelve content tests and source regeneration check. Its graphical and physical-input validation subsequently passed: one Mine strike/five wear/two dirt in the bounded fixture, plus pre-impact panel cancellation with zero edits/wear. See the latest playtest entry. No live original tool-event trace is claimed.

## API and action ownership

`PeSandboxActions` lives outside `PeGame` and saves. The host initializes or cancels it on new game, load, import, pause/UI/focus interruption, equipment change and other permissions loss. `pe_sandbox_actions_step` advances exactly one 1/60 **scaled game second**. Render frames can contain zero or multiple fixed steps; drawing must only read `pe_sandbox_actions_pose`, which returns stable item instance, held state, source clip name and authored clip time. There is no independent renderer timer.

Call the action step before gameplay movement, rebuild the world collision snapshot if a sample changes, and pass `action.stamina_lock` in `PeInput.stamina_action`. Suppress movement while the action is active. The ending action frame retains the stamina lock; normal regeneration begins only after the source minimum .1s rest delay. The frontend's stationary, grounded, third-person and modal/asset capability gates are an explicitly bounded host policy, not a complete source motion-mask implementation.

All four supported tools charge their source stamina cost on start and at each continuing successful event. Low stamina is allowed: each of the serialized thresholds (shovel40/20, pickaxe and both axes50/20) multiplies the tool's base speed by .9, then speed is clamped to [.5,1.5]. A normal input release latches ending; re-press does not silently cancel that ending request. Dig has the source five-second release fallback; Fell retains the source three seconds since its last hit when ending. Broken tools finish their exit without producing additional edits. Immediate cancellation applies no later event and refunds no already-spent stamina.

Dig initially captures `pe_world_dig_target`'s exact sample indices. The first event keeps that target even if the later indicator is invalid. Later ChangeTarget and DigTerrain events use a current valid indicator; an invalid later indicator suppresses the attempted swing. A valid empty locked sample still consumes attack wear and the continuing stamina charge, matching the source event ordering. The shared indicator retains the strict3m reach from feet+up1; it is not a camera3m test.

Fell requires the **same** tree selected by the camera ray (origin shifted back .5m, range100m) and the feet+up1, forward2m ray. The frontend supplies both indices through the input contract. Once started, the action retains its selected tree even if the later pointer looks elsewhere. The world view now exposes a source trunk query, distinct from its render-triangle query. `Assets/Prefabs/tree-Ambient-Occlusion/tree11_grassland.prefab` CapsuleCollider13600000 has center(-.1,3,-.2), radius1, height7, Y axis, enabled/nontrigger. Its MeshFilter3300000 external GUID `71fbbe8530d15a4f8408390cd27df9d4`/path4300000 matches the recovered orgtree mesh; prefab SHA256 is `a94f5931d8fa6cab466004968f0dc73f1eec41fd6c8919874f2f4ae9fc0f442b`. The exporter records this exact identity and writes `tree-collider.pesc`; the source RSubTerrainMgr creates the translated/scaled collider on layer21. Current procedural trees use unit scale. This verifies the model/collider pairing, not their original Adventure species assignment, spawn distribution, size or resource definitions. Origins strictly inside the trunk do not produce that collider's ray hit, matching Physics.Raycast behavior.

## Resource transactions and remaining substitutions

`pe_game_dig_sample` and `pe_game_cut_tree` apply only the resource transaction. They do not charge stamina, wear, or a second generic cooldown. The action host calls them once per authored event and owns those costs. The legacy instant `pe_game_mine`/`pe_game_gather` interfaces still exist for legacy fixtures and explicitly provisional fallback tools; calling both paths for one input would double-edit and is prohibited by the host contract.

Mining retains source item attack plus player attack, terrain damage attenuation, byte reduction, material/resource lookup and actual per-removal production. Radius .49 selects one sample; larger tools, bonus production and general skill targeting remain out of scope. Capacity failure leaves density, inventory, RNG, wear and the follow-up stamina charge unchanged while consuming that animation opportunity. Initial action stamina remains spent. This capacity reservation is an intentional conservation repair rather than replication of an unchecked source item-add failure.

General source tree HP starts at255 and the selected tools contribute CutDamage28/46. Current procedural trees still use **unit resource duration/height/width factors and their stored wood yield**. A source animation clock does not make those provisional tree values a recovered Adventure species table. Depletion commits the stored yield once, clears remaining/HP and lets the renderer remove the actual tree. There is no seven-hit tutorial condition, automatic script grant, mission advance, fake stump, or resource award from merely clicking a tree.

## Reproducible host fixtures

`tests/sandbox_action_fixture.c` creates separate Adventure dig/fell saves through the public starter, quest acceptance, equipment and shortcut APIs. Only player position and camera angles are deliberately arranged as controlled fixtures. It chooses an actual within-reach terrain sample for shovel12 and a safely grounded position whose two source trunk rays select the same live tree for axe26. A temporary copy must produce the expected authored hit before either pristine state is saved; no validation-hit resource or wear is retained in the files. `--inspect SAVE.pesave` reports tool wear, resource totals and every tree's remaining yield/HP for the operator's later manual result. `--mine OUTPUT.pesave` adds an independent item19 fixture with a real Mine-event probe. `--migration OUTPUT.v4.pesave` creates a controlled old-format tree overlap, verifies safe native migration and a separate v5 roundtrip, and checks that loading leaves the original v4 file byte-identical. The helper opens no window and supplies no desktop input.
