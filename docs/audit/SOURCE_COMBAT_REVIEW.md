# Combat, movement and equipment: fresh source-first review

2026-10-06. Read-only review of the current C tree, original C# and existing source/asset audits. This report supersedes the **priority list**, not the historical evidence, in [SOURCE_FIRST_COMBAT](SOURCE_FIRST_COMBAT.md). It does not launch either game, modify a save, or qualify new animation output. Only this document is added.

Passive HP recovery, stamina/comfort scheduling, historical capsule contact and contact-responsive attack playback now have C owners. Starter clothing, Sword wear, shield ownership/damage and the disconnected shield action owner also exist. They must not be reported as wholly missing again. See [recovery](PASSIVE_RECOVERY.md), [stamina](STAMINA_RECOVERY.md), [history](MELEE_CAPSULE_HISTORY.md), [playback](ATTACK_PLAYBACK.md), [outfit](STARTER_OUTFIT.md), [wear](SWORD_WEAR.md) and [shield action](SHIELD_ACTION.md). Ordinary visible shield activation is still gated; headless shield admission is not the remaining animation problem.

The five targets below can begin with ordinary source/data extraction and deterministic tests. No further humanoid reverse engineering or broad original-game playthrough is a prerequisite for their logical contracts. Their presentation and engine-controller limits are separate.

| Priority | Deliverable | Smallest useful offline result | What still needs integration or observation |
|---|---|---|---|

## 1. Admit slow grounded attacks through the ordinary branch

**Source contract.** [`Action_SwordAttack.ApplySkill`](../../Assets/Scripts/PeEntity/Cmpt/Motion/PEAction/Action_Sword.cs#L188) prioritizes air, then water, then strict comparisons of the full movement-velocity magnitude: sprint, moving attack, otherwise ordinary attack. It does not require the ordinary branch to start at zero speed or with movement keys released. The installed4.5/7 thresholds are already qualified in [SANDBOX_RUNNING_KNIFE](SANDBOX_RUNNING_KNIFE.md); the C# field defaults4/6 are not the installed values.

Accepted attacks own their movement. [`UpdateSkillState`](../../Assets/Scripts/PeEntity/Cmpt/Motion/PEAction/Action_Sword.cs#L209) derives horizontal velocity from `anim.m_LastMove / Time.deltaTime`, caps the difference from current horizontal velocity at12, and submits that request to the motor. `EndImmediately` at157 clears horizontal velocity and inertia. `OnStartAttack` at358 charges stamina and refreshes targeting; combo admission is not permission to keep ordinary locomotion running beneath the attack.

**Current C gap.** [`pe_sandbox_melee.c`](../../rebuild/src/pe_sandbox_melee.c#L15) requires no requested movement and horizontal speed≤.05 for ordinary starts and continuation. Running starts cover only `4.5 < speed <= 7`. This leaves slow walking and decelerating attacks unavailable. [`pe_running_attack_motion.c`](../../rebuild/src/pe_running_attack_motion.c) already supplies the bounded running displacement/12m/s change-limit path; it is not an ordinary-attack root curve.

**Minimum port/tests.** Separate source variant selection from supported-presentation capability. Test zero, .05, walk speed, exactly4.5, just above4.5, exactly7, above7, full XYZ magnitude, and air/water precedence. Then extend the accepted-action movement owner so continuing to hold a movement key neither cancels the admitted attack nor produces a second locomotion displacement. Retain one body/blade/defence/contact clock, modal fresh-press ownership and atomic rejection before stamina debit. Test collision, interrupted actions, combo transitions and consumed intervals.

Existing Attack6–9 poses can be reused, but those local posed meshes do **not** establish ordinary root displacement. Inspect stored root channels and existing capture provenance first; missing root evaluation is a specific remaining input, not a reason to replay the hunt. A documented zero-motion adapter would be a deliberate limitation, not source parity. Do not merely delete `stationary_allowed` and claim the motor contract is fixed.

## 2. Apply force/reaction consequences of admitted damage

**Source contract.** [`SkTriggerEvent.Exec`](../../Assets/Scripts/SkillSystem/SkTriggerEvent.cs#L47) sets event force, applies attribute modifications and dispatches effects. [`SkAliveEntity.ApplyForce`](../../Assets/Scripts/SkillSystem/SkAliveEntity.cs#L457) routes permitted effects through `Motion_Beat`. [`Motion_Beat.ApplyMoveEffect`](../../Assets/Scripts/PeEntity/Cmpt/Motion/Motion_Beat.cs#L87) scales force and thresholds using separate angle curves and the airborne multiplier, then uses strict `<` threshold comparisons to select Null, Whacked, Repulsed, Wentfly or Knocked. The final two branches both request Wentfly in this implementation; do not silently change that to match the enum names.

The curves come from the instantiated model's `BiologyViewRoot.beatParam`, assigned on `View_Prefab_Build` at203, not merely the class defaults in [`BeatParam`](../../Assets/Scripts/PeEntity/Cmpt/Motion/PEAction/Param/BeatParam.cs). The existing trigger rows10100/10400/10250 and shield buff30200177 are starting inputs, not sufficient by themselves to infer every result.

**Current C gap.** [`pe_hunt_combat.c`](../../rebuild/src/pe_hunt_combat.c#L161) commits incoming HP, clothing/shield wear and hit counters, but no corresponding force/reaction action. Outgoing contact likewise does not supply the target's full reaction lifecycle. Correct capsule contact and HP formulas do not reproduce interruption or displacement.

**Minimum port/tests.** Export the actual player/hare BeatParam bindings, curves, event forces and action-relation rows. Start with an allocation-free decision function and source action request/cancellation state; test threshold equality, airborne and shield thresholds, zero force, permitted/denied hits and same-tick lethal hits. Integrate resulting changes with the existing staged combat transaction, preserving rollback if a later target is invalid. Random hit-IK weight is separate from threshold selection and should take an injected draw in tests.

[`Action_Whacked`](../../Assets/Scripts/PeEntity/Cmpt/Motion/PEAction/Action_Beat.cs#L9) ends on `HitAnimEnd`, not an invented stun timer. `Action_Repulsed` at83 uses bound force→velocity/time curves and a stop/wentfly lifecycle. It also calculates `m_IsBlockRepulsed` using `m_MoveDir` **before** assigning the new direction at93; retain this source ordering in the audit rather than replacing it with an assumed incoming-facing test. A damage-facing cone must not be inferred from that reaction check. Ragdoll, IK and unsupported reaction clips remain presentation/physics work; first ship the proven headless contract without claiming full hit reactions.

## 3. Allow supported clothing replacement with one owner per instance

**Source contract.** [`EquipmentCmpt.PutOnEquipment`](../../Assets/Scripts/PeEntity/Cmpt/EquipmentCmpt.cs#L284) checks ragdoll state, Equip component, sex, duplicate ownership and enabled skill-tree restrictions. It gathers all items whose `equipPos` bitmasks overlap, checks their removal permission and receiver capacity, and only then changes the equipment list, returns displaced items and applies/removes effects. [`TakeOffEquipment`](../../Assets/Scripts/PeEntity/Cmpt/EquipmentCmpt.cs#L421) similarly checks receiver capacity first. Equipment buffs are explicit calls at497/507, not a permanently increased player base defence.

**Current C gap.** [`pe_outfit_valid`](../../rebuild/src/pe_outfit.c#L14) supports only the exact fixed three starter item IDs; `pe_outfit_state_valid` also requires an occupied Adventure outfit. Wear and breaking those pieces are implemented, but taking off or replacing one with a bought/crafted piece is not. Primary and shield are bag-owned references; the current outfit is separately owned. Generalization must retain these explicit identity distinctions rather than duplicating bag records for a worn item.

**Minimum port/tests.** Export one supported armor family's masks, sex, maximum durability, buffs and replacement model references. Define a staged transfer returning the displaced exact instance, preserving current wear and debiting the new item once. Tests: overlapping multi-slot equipment, full receiver, empty slot/take-off, wrong sex, enabled skill restriction, nonremovable item, duplicate identity, broken-item effects and failure rollback. Extend PECS validation/migration explicitly; old fixed outfits must retain their IDs/wear. A successful headless swap does not permit an invisible armor buff: gate normal use on matching body parts/defence representation. No original gameplay is needed to discover slot or capacity rules; a short native equip/save/reload check is the later acceptance step.

## 4. Port item revival as its own source-ordered lifecycle

**Source contract.** [`UIRevive.BtnClick_OnRevive`](../../Assets/Scripts/Chenzhi/NewUI/Scripts/PE_GameUI/NGUIScripts/UIRevive.cs#L323) requests `DoRevive(false)` first and calls `UseItemCmpt.Revive()` only if the action is running. [`Action_Revive`](../../Assets/Scripts/PeEntity/Cmpt/Motion/PEAction/Action_Live.cs#L577) checks get-up readiness, floors HP to1 if necessary, restores oxygen/stamina, freezes physics and sends State_Revive. Its end removes the freeze and re-enables injured colliders with1.5s delay. It does not itself assign the final item-healed HP.

[`UseItemCmpt.Revive`](../../Assets/Scripts/PeEntity/Cmpt/UseItemCmpt.cs#L250) locates item937 and invokes `Use`; ordinary `Request` deliberately rejects937 and dead users at268. The separate item→skill→event chain remains essential; the row chain is937→20150031→53/59: raw attribute8 decreases25 and HP becomes summed HPMax×`.333f`. Attribute8 is Comfort in [`AttribType`](../../Assets/Scripts/PeEntity/Cmpt/PESkEntity.cs#L8). The skill’s `_cond=False` is its loop condition, loaded into `_condToLoop` by [`SkInst`](../../Assets/Scripts/SkillSystem/SkInst.cs#L135), not a prohibition on its first execution. Re-export those rows and their execution order with the port instead of converting the UI label into full healing.

**Current C gap.** The native death path at [`pe_sandbox_view.c:923`](../../rebuild/src/pe_sandbox_view.c#L923) instructs the player to load a save. There is no item937 lifecycle. Current HP/comfort, inventory ownership and recovery remount owners provide useful foundations. The current [generated catalog](../../rebuild/generated/pe_content.c#L209) already contains937, recipe114 and an Adventure starter grant of ten shots at443. This makes the missing use path especially valuable: usable source resources are already present in native inventories. It can be prioritized ahead of new movement work when the next goal is reducing forced checkpoint reloads.

**Minimum port/tests.** Model action admission, initial revive effects, item skill admission/debit and get-up completion as distinguishable stages. Test source order, missing item, denied get-up, denied skill, exact one-item debit, HP fraction and comfort clamp, restored stamina, repeated UI requests, collider grace, and reset of old attack/history/sensor state without erasing earned hunt progress. A native all-or-nothing retry transaction can be useful, but must be labeled an adapter: the source UI invokes the action before item use and does not check `UseItemCmpt.Revive()`'s return value. Do not claim a source rollback that is absent.

The no-item Cancel/nearest-fast-travel path is a different contract involving labels and mission cleanup; it must not quietly become item937 revival or an invented starting-town teleport. Get-up visuals are the specific remaining presentation question. There is no need to repeat combat to discover the numerical revive contract.

## 5. Replace the jump/air-control approximation as a bounded movement owner

**Source contract.** [`Action_Jump`](../../Assets/Scripts/PeEntity/Cmpt/Motion/PEAction/Action_HumanMove.cs#L816) checks stamina against the scaled cost, debits on admission, enforces a motor minimum speed and applies upward impact `sqrt(20*m_JumpHeight)`. At875 its update refreshes the consumption timestamp, retains a starting local movement vector, and combines new input with that vector using `m_JumpMoveF`. Ground/water exit waits for strict `elapsed > m_JumpDT`; end/gravity times also use strict tests. The support test is a capsule cast with a serialized layer mask at960.

[`Action_Fall`](../../Assets/Scripts/PeEntity/Cmpt/Motion/PEAction/Action_HumanMove.cs#L978) has a separate admission/exit lifecycle and interpolates desired air movement using `5*Time.deltaTime`. These are action rules; they do not by themselves reproduce HumanPhyCtrl/Rigidbody collision and gravity. Export actual serialized parameter/motor bindings before using the C# initializer values as installed constants.

**Current C gap.** [`pe_game.c:405–426`](../../rebuild/src/pe_game.c#L405) uses the shared native support/collision adapter but resets horizontal velocity directly from current input, jumps with fixed vertical7 and applies gravity20. It does retain a bounded jump-active stamina timestamp and three-second timeout. Those existing pieces are not evidence that source inertia, support grace or air steering is implemented.

**Minimum port/tests.** Add a pure jump/fall state receiving actual support, water, input, body orientation and elapsed time. Export parameters, preserve one velocity/displacement owner, and test input reversal after takeoff, no-input retained momentum, just-before/equal/after landing grace, ceiling collision, fall handoff, accepted stamina debit and cancellation. Keep native collision geometry intact; compare source requested velocities separately from the resulting sweep. A later short native jump/landing check and an existing-or-batched reference trajectory establish controller feel; no new animation solver is required to implement the action policy. Do not add guessed fall damage as part of this change.

## Deliberately separate work

The pure ordered [Sword targeting helper](SANDBOX_COMBAT_NEXT.md) is already tested but not host-integrated. Source `ChangeAttackTarget` depends on overlap enumeration, duplicate views, permissions and an IK aim path; wiring a nearest-hare shortcut would not preserve that contract. Pounce and richer hare arbitration likewise remain real gaps, but need coherent attack movement/poses and the behavior-tree context rather than a guessed leap timer. They are separate from the smaller rule/ownership increments above.

The existing shield action owner can be integrated once composed body/tool/defence poses are qualified. Its logical tests do not need repeating merely because presentation remains incomplete. Full four-kill native completion, partial-progress reload and ordinary control feel remain acceptance checks; another general hunt session is not prerequisite evidence for the C# rules enumerated here.

Verification of this audit is source/path/claim inspection only. No gameplay tests or new physical parity claims are added.
