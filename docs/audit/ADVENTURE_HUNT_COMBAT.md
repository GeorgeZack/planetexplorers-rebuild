# Adventure9126 bounded combat integration

The sandbox connects the six observed hare anchors to a native encounter, stationary and bounded running Knife33 contacts, incoming hare melee, authoritative HP and saved four-kill progress. This is an implemented bounded controller, not a recovery of the original behavior tree. The full-HP lifecycle regression below now joins real resolver deaths, partial-progress saves, reload, cleanup and return rewards in one test. Native four-kill completion and partial-progress reload were accepted on October 7 ([acceptance](HUNT_ORDINARY_ACCEPTANCE.md)); see also the [running-attack checks](SANDBOX_RUNNING_KNIFE.md).

## Ownership and gameplay path

[`pe_adventure_hunt`](../../rebuild/src/pe_adventure_hunt.c) retains the original4524 destination at source(-349,19.5,233). Strict15m XZ arrival advances travel state1 to encounter state2. [`pe_sandbox_view`](../../rebuild/src/pe_sandbox_view.c) then prepares [`pe_hunt_combat`](../../rebuild/src/pe_hunt_combat.c) once, using the current world/collision snapshot, recovered hare PEAC/PEHB, complete Knife33 assets and the auxiliary player defence actor. Missing assets or unsupported geometry leave the encounter unavailable; no fallback creature or target is generated. Loading resets transient combat and prepares again from the loaded progress.

[`pe_hunt_encounter`](../../rebuild/src/pe_hunt_encounter.c) stages all six captured source anchors, original identities, scales, HP/attack/defence and faction values before committing. Exact captured XZ is retained subject to normal contact skin during supported settling. Each actor has one authoritative current HP field; its movement state's maxHP remains a maximum. Motion, animation, outgoing damage, stamina and kill credit are staged atomically. Rendering uses the same actor clip/time and scale used by contacts. Dead actors are omitted; corpse rendering and loot are absent.

The saved kill count is owned by `PeGame`, never inferred from missing rendered actors. Real positive-to-zero prototype13 death notifications credit the objective once. The generic death boundary does not add player-last-hit, mission-cohort or radius requirements that are absent from the inspected source. The present host produces deaths from its bounded cohort only. Four credited deaths remove the remaining owned actors and enter return-pending state3. [Mission9127 return discovery, script rewards and durable replies](ADVENTURE_HUNT_RETURN.md) are implemented. Town Defense9077 and the skill-tree flow remain unavailable.

## Perception and attack adapters

The [source encounter audit](ADVENTURE_HUNT_ENCOUNTER.md) and [`pe_hare_perception`](../../rebuild/src/pe_hare_perception.c) distinguish vision, hearing, collection and damage permission. The host evaluates the recovered animated head mount, uses source vision20/angle60/axis(-.5,1,0), hearing15 with occlusion, and the dedicated perception collision query rather than the camera mask. Vision, hearing and target collection advance once per display frame at their source component cadences20/16/15. Sensor geometry and faction/threat inputs are source-derived; this is not a fabricated20m hostility sphere.

The current controller supplies one player candidate, known Adventure force conflict, initial threat5 and damage relation1. Once this sole candidate supplies positive threat, hostility is retained until player death. General target ranking, reputation changes, carriers, sharing/forgetting threat and full TargetCmpt arbitration remain outside this adapter. Player target center/radius/height use the native capsule rather than a captured full live bounds system.

At most three creatures attack concurrently. The controller uses source-derived melee eligibility and available attack candidates with its own deterministic selection stream. It does not implement the complete behavior tree, branch probabilities, pounce or original melee-slot arbitration. Attacking creatures hold their position; attack root motion is not reconstructed. Other living creatures use the generalized collision-aware hare movement/patrol helper.

[`pe_hare_skill`](../../rebuild/src/pe_hare_skill.c) schedules exported source prepare/pre/main/post/ending durations at60Hz separately from [`pe_hare_attack`](../../rebuild/src/pe_hare_attack.c)'s normalized animation/contact windows. Guide identity is zero-based in C, independently of the authored window index. Positive waits consume complete fixed ticks and discard excess on transition; zero phases settle immediately. This is a native coroutine scheduling adapter, not measured Unity update-order parity. The BTMelee host sends no Sword/Gun skip requests. A contact requires both the current skill's external-execution/main flag and an open authored forearm window.

[`pe_hare_damage`](../../rebuild/src/pe_hare_damage.c) evaluates source forearm and player defence capsules and the shared damage formula against caller-owned HP. Successful targets are deduplicated per actual guide across both forearms. Current host damage is noncritical in both directions; critical RNG, rigid/force responses, XP, hurt-animation response and other effect side effects are absent. Player blade contacts are processed before surviving hare forearms within a native tick, an explicit ordering choice.

## Exact player defence pose

[`pe_sandbox_actor_body_pose`](../../rebuild/src/pe_sandbox_actor.h) shares world-render pose selection and returns current clip names, sampled seconds, duration and loop policy, including the supported locomotion blend. It covers twelve locomotion states, Knife Attack6–9 and RunSwordAttack, and Spade/Felling/Mine1–3, respecting equipped-instance and cancellation guards. The host resolves the same names and blend samples in the auxiliary player defence actor and rejects incompatible or missing clips; it never substitutes idle. Active blade contact uses the same unblended authoritative knife stage/time that the renderer presents.

The initial [defence exporter](../../rebuild/tools/export_player_defence.py) combined four closed compatible original bakes into19 clips and602 sampled poses. [Directional recovery](DIRECTIONAL_PLAYER.md) and the [running-pose extension](RUNNING_PLAYER_POSES.md) now supply30 clips and935 poses in `reference-assets/player-defence/player-defence.peac`, retaining23 joints and16 source capsules. Capture hashes, clip clocks and geometry/inverse-bind compatibility remain checked. The auxiliary23-joint actor is distinct from the rendered torso's17-joint skin; its PEHB must be loaded against the compatible auxiliary actor. Native locomotion blending is a presentation adapter shared with capsule queries, not recovered Unity TRS blending or procedural IK.

## Pause, death and saves

Inventory and other modal UI suspend encounter sensing/combat, in addition to pause/unfocused suspension; this is a native usability policy. The existing pointer-release ownership rule still prevents closing a modal from also swinging. Unsupported movement during a stationary action, stow, death, camera/equipment change and load cancel the player's knife action. Qualified running actions instead consume their authored horizontal root motion through the shared collision sweep. Player death cancels active contact clocks and offers loading the saved checkpoint through the pause menu. There is no respawn system.

The retained PECSv11 layout appends one little-endian32-bit `hunt_kills` field to the literal v10 payload. Versions1–10 infer0. Valid current state/count pairs are: none/travel with0, encounter state2 with0–3, and return/presentation/completed states3–6 with4. V12 introduced states4–6 without adding bytes; current v13 adds the separate medpack cooldown. Earlier versions reject state values introduced later. Invalid combinations fail load/save atomically; the deployed-instance and earlier world/progression prefixes remain unchanged.

Only quest progress is saved, not transient hare HP/positions, threat, skill clocks or graphics state. Reloading active state2 restores the saved count and recreates all six **pinned full-HP** actors from the chosen reference cohort. Two original zero-kill reloads actually produced different random cohorts; this fixed reconstruction is an explicit adapter. Original nonzero-kill reload behavior has not been physically verified. Do not describe native saved-count coverage as that missing original observation.

The player remains at500HP with all ten medicine-reward medpacks unused. Consequently this test proves neither walking the route, surviving retaliation, successful manual targeting, nor four kills in ordinary play.
