# Sandbox world alignment audit

Status: source and C implementation inspection on 2026-10-03, with the parent agent's original Single Player Build/Adventure observations added below. This document changes no runtime behavior. It covers the default C sandbox, not the separate recovered tutorial frontend. These narrow original fixtures resolve mode behavior; they are not a completed terrain/camera/controller comparison. Existing native tests establish implementation behavior, not Adventure or Build parity.

The highest-value next step is to share the training frontend's mesh/capsule collision and source action clocks with the sandbox. That would improve the current small playable world without waiting for the much larger original procedural generator and streaming port. A matching seed, larger bounds, or recovered textures alone would not make the present sandbox an original Adventure world.

The subsequent [live alignment report](SANDBOX_ALIGNMENT.md) records the completed original Adventure/Build inspection, exact settings, saves and screenshots. It does not establish C generator or physics parity.

## Adventure and Build are distinct modes

Source [RandomMapConfig.cs](../../Assets/Scripts/PuJi/Town/Tool/RandomMapConfig.cs) defines Adventure and Build scene modes, game types Cooperation/VS/Survive, default seed666 and terrain height128. Its size choices are40,20,8,4 and2km square; default boundaries are centered at±20,000. The Story constants18,432×2,944×18,432 are not the Adventure extent. Some configuration affects town/mineral/vegetation generation even when the visible terrain seed is unchanged.

[SingleGameInitData.cs](../../Assets/PeWorld/SingleGameInitData.cs) independently supplies Adventure item1289 and500 money, with item1743 conditional on `openAllScripts`; non-demo Build receives item1291 and500 money. These are source item IDs, not an assertion about unpacking their full contents. The default C sandbox starts an empty inventory and nearby synthetic trees instead. Its initial time is94.35 days; [GameTime.cs](../../Assets/Scripts/Global/GameTime.cs) also defines a separate Build start94.50. The26-hour day and12× normal clock rate are already represented in C.

The observed Single Player Build construction debit bypass is now traced precisely. [SingleGame.cs](../../Assets/PeLauncher/SingleGame.cs) `SingleGameBuild.LoadBuild` sets `PlayerPackageCmpt.LockStackCount=true` (line556); Adventure sets it false (line480). `PEBuildingMan.OnCheckVoxelModify` still compares `pkg.GetItemCount` with the grouped rounded cost, then calls `pkg.Destory`. [PlayerPackageCmpt.cs](../../Assets/Scripts/PeEntity/Cmpt/PlayerPackageCmpt.cs), lines220–248, makes `Destory` and the two `DestroyItem` overloads return success without reducing inventory when `LockStackCount` is true. This preserves resource-availability checks while preventing the successful debit. It is different from `PEBuildingMan.IsGod`, which returns before those checks, and from `PeGameMgr.unlimitedRes`, whose multiplayer configuration exists separately. Do not collapse these flags into one universal god mode.

Time freezing also has a direct source path: [PlayerTypeLoader.cs](../../Assets/PeLauncher/PlayerTypeLoader.cs) `InitNew` sets Build day94.50 and `Timer.ElapseSpeed=0`, while Adventure sets94.35 and normal speed12. Half of a26-hour day is13:00. This freezes the world clock, not Unity simulation or `PlayTime`, which `GameTime` advances separately at speed1. Build also uses `LoadRandomTerrainWithoutTown`; the Adventure launcher uses the with-town path. The Build loader's comment describes resource-unlimited Adventure without monsters/NPCs, but complete population behavior still needs its own subsystem audit.

## Terrain generation, coordinates and streaming

The source authority is `Assets/Terrain/Voxelform2/Voxelform/Source/Scripts/Voxel/VFDataRTGen*.cs`. `VFDataRTGen.cs` initializes separate terrain/cave/mine/river/biome noise families from fixed seed offsets, and constructs a cache key from the broader configuration. `RandomMapConfig` derives town and mine seeds separately. [SimplexNoise.cs](../../Assets/Scripts/System/SimplexNoise.cs) uses legacy `System.Random`; its permutation swaps each index against `Next(0,255)`, not an inclusive255 range. Its double constants incorporate float `Mathf.Sqrt` results. Preserve those details and evaluation precision before expecting exact byte densities.

The legacy importer is already a useful independent foundation: [pe_legacy.c](../../rebuild/src/pe_legacy.c) validates `.voxelform` offsets/LZ4 and expands uniform/dense chunks at LOD0–4. Cropping into `PeWorld` is deliberately LOD0 only. Crop coordinates are metadata for the sandbox: the camera/player and drawn terrain use local coordinates, unlike training's explicit source-origin offset. A future global world adapter must define this conversion once for terrain, blocks, actors, rays and saves. Negative global coordinates require floor division/modulo, not C truncation aroundzero.

Source MC corner/edge tables, threshold128, interpolation, winding and interior gradient normals are recovered. Crop-edge gradients clamp to available samples; full external halos are absent. Original material blending/packed attributes and transition extraction are absent. See [world formats and generation](WORLD.md) and [terrain geometry parity](TERRAIN_PARITY.md).

For streaming, introduce chunk keys and immutable sampled inputs first; keep generation, loaded edits and GPU ownership separate. A queued result must carry both chunk identity and revision so an old result cannot overwrite a later edit or reused cache slot. Preserve edits outside the current resident set. Treat `.terra` generation caches as disposable, not the save authority. Start at a single LOD with correct adjacent halos; only then add the source Transvoxel transitions. Merely increasing `PE_WORLD_X` would retain the bounded architecture and multiply full snapshots and scanning costs.

## Collision and movement: practical reuse first

`pe_world_raycast` and `pe_world_height` intersect MC triangles, with an explicit immediate-inside density case. `pe_world_collides` instead probes a cylinder at up to.2m vertical intervals and eight radial directions using trilinear density. Those surfaces are mathematically different: the existing single-solid-sample ray regression demonstrates an octahedral MC surface versus the implicit density surface. Accordingly a matching mining ray does not prove that feet, walls and ceilings collide with the displayed surface. Sparse probes are also not a continuous sweep.

Sandbox player radius is.30m and height1.75m. Movement substeps are bounded to about.08m, resolve x/z/y separately, and attempt seven.05m lifts when blocked horizontally. Block45 overlap uses the real cube/ramp solid against a player AABB; this is more accurate than treating ramps as cubes but remains a different player shape. Placement uses27 density probes per cell, so terrain/construction exclusion is sampled rather than an exact intersection. Save validation repeats these rules; changing only the live controller could make valid new positions fail to save or make old saves unsafe.

Reusable training pieces:

- [pe_scene_collision](../../rebuild/src/pe_scene_collision.h): bounded triangle BVH, raycast, strict capsule overlap and continuous translation sweep. `pe_scene_from_mesh` copies a mesh with an explicit origin.
- [terrain view cache](../../rebuild/src/pe_training_terrain_view.c): constructs render geometry and collision from one MC result and replaces snapshots by revision. This is a pattern to generalize, not a tutorial-specific dependency to import wholesale.
- [training movement](../../rebuild/src/pe_training.c):.30×1.80m capsule, earliest room/terrain/build contact, slide/step/ground support and slope handling. Extract shared controller policy without embedding missions, tree lessons or training inventory into `PeGame`.
- [training construction](../../rebuild/src/pe_training_build.c): actual Block45 triangles, capsule exclusion and collision snapshot. It is bounded and dirt-only; retain sandbox mixed-material transactions when sharing geometry helpers.

The BVH is a surface collider, not a general solid-volume classifier. Retain a separate embedded-spawn/loaded-state policy, especially for closed solid chunks, out-of-world coordinates and edits under the player. A robust shared controller is still a replacement for Unity physics: climbing, swimming, moving platforms, root motion, ragdoll and full motor/action state require separate work. Source owners include `Assets/Scripts/PeEntity/CharacterMotor/PEMotor*.cs` and `Cmpt/Motion/Motion_Move*.cs`.

## Save and reload contract

`PECS`v3 is explicitly little-endian, with length/version and FNV32 payload integrity, not authentication. It serializes the entire bounded volume, player/inventory/tool state, RNG, timers, crafting and construction/tree state. Load validates into a temporary game, accepts v1/v2 migrations, and commits only on success. Save writes a same-directory temporary file, flushes/fsyncs it and renames it. No directory-fsync crash-durability guarantee is implemented.

Original archivev5 and modified-terrain version1606230 are unrelated formats. A complete original save includes subsystem and world/yird state beyond terrain; `.voxelform` import is geometry import, not save import. Current C world replacement preserves possessions but discards world-bound trees/cells/proxies and resets movement; that operation is not travel between persistent Adventure regions.

Before streaming, version a configuration/coordinate identity and chunk edit archive. Save edits plus deterministic generation identity, with an explicit migration strategy for existing full-volume v3 saves. Preserve active inventory transactions and stable equipment IDs. Do not persist pointers, GPU/BVH handles or transient worker jobs. A renderer/physics upgrade must update save-spawn validation and migration tests in the same change.

## Dependency order and effort/risk bands

Bands describe scope, not calendar promises. “Bounded” means existing primitives with a narrow contract; “substantial” spans several runtime owners; “major” needs a new subsystem and reference fixtures.

1. **Bounded scope, moderate behavior risk:** record an original Adventure/Build baseline and explicit world/mode metadata; add captured deterministic fixtures before changing semantics. Correct labels/controls only where source mode is established.
2. **Substantial scope, high regression risk:** share render-derived capsule collision and controller geometry with the sandbox, including save validation and placement exclusion. Reuse the tested BVH; do not simultaneously port streaming.
3. **Substantial scope, moderate integration risk:** connect recovered actor/camera and source tool clocks through shared adapters, retaining one inventory owner and actual edit transactions. Adopt the bounded source point brush while retaining mixed materials.
4. **Major scope, high data-lifecycle risk:** chunk storage, global coordinates, halo synchronization, edit persistence, bounded resident cache and stale-job rejection at one resolution. Keep original seed parity a separate acceptance axis.
5. **Major scope, high deterministic-parity risk:** legacy RNG/noise golden tests, configured column terrain, caves/minerals/painting, then towns/water/vegetation. Port ordered stages and compare intermediate outputs; do not debug only final screenshots.
6. **Major scope, high geometry/render risk:** LOD transitions, original terrain/water shading, streamed vegetation collision/depletion and complete building/creation systems. Old archive import and multiplayer authority require separate designs.

The reusable mesh is the already recovered `TrainingManager_New/HoloTree/orgtrees/orgtree`, installed `resources.assets` Mesh6039, 3,150 source vertices and 4,216 triangles. Its raw source mesh SHA256 is `f4260d9f8fefcd07257ef753ac01d53dd7934b5671ebcb51ce37ad817395fea4`. The new exporter applies the inverse recorded affine matrix to positions and the corresponding inverse-transpose transform to normals, reverses triangles if needed to undo a mirrored authored hierarchy, and retains UVs. It removes tutorial translation `(10.92083058,1.58233070,11.97933918)` and approximately−90° yaw. The resulting mesh-local bounds in meters are `(-2.65711046,-0.24681623,-3.46337006)` through `(2.15026356,7.78633261,2.08653378)`. The source material is `Grassland_tree_B`, installed Material1654, diffuse Texture5017. Depletion is read directly on every draw: `remaining>0` draws the live tree; `remaining==0` draws nothing. There is no second renderer-owned health/resource ledger and no cached instance state to survive a load incorrectly. The old cylindrical stump is intentionally absent. Its CPU triangles are the same local positions/indices used by rendering, with each current tree translation applied. An axis-aligned bounds test precedes the triangle loop. It handles either face direction, exact range endpoints, origins on triangles and non-unit direction lengths; zero/nonfinite directions and malformed tree state fail without changing outputs. Valid misses return index−1 and the supplied range. This lets a host evaluate the source action's separate camera100m and player-forward2m queries against one mesh representation, without inventing an AABB hit as the actual contact.

### Matching original trunk interaction capsule

A scan of all source prefabs referencing `orgtree`’s external mesh GUID found [tree11_grassland.prefab](../../Assets/Prefabs/tree-Ambient-Occlusion/tree11_grassland.prefab). Its MeshFilter3300000 and the training mesh both reference GUID`71fbbe8530d15a4f8408390cd27df9d4`, Mesh4300000. Its root has identity local position, rotation and scale. The source prefab SHA256 is `a94f5931d8fa6cab466004968f0dc73f1eec41fd6c8919874f2f4ae9fc0f442b`. CapsuleCollider13600000 is **enabled, nontrigger, Y-directed**, with center`(-0.10000000149011612,3,-0.20000000298023224)`, radius`1m`, total height`7m`; the cylindrical axis therefore extends±2.5m around the center, capped by radius1 hemispheres. This is an exact source match rather than the earlier unrelated `tree03_01` capsule. The exporter decodes both prefabs and verifies mesh GUID/path identity and identity root transform on every export/check.

The new36-byte `tree-collider.pesc` sidecar is little-endian: magic`PESC`, u32version1, f32centerXYZ/radius/height, u32direction1, u32flags1(enabled/nontrigger). The native loader validates exact file length, version and allowed direction/flags, then requires all five numeric fields to equal the generated source collider before uploading any model. A well-formed capsule from another tree is rejected. `pe_sandbox_world_view_ray_trunk` applies each current tree position at unit scale and finds the nearest live analytic capsule hit. It preserves normalized metric distance and atomic invalid-input behavior, while strictly inside origins skip that tree. This is consistent with the documented [Unity5.4 Physics.Raycast inside-origin rule](https://docs.unity.cn/540/Documentation/ScriptReference/Physics.Raycast.html). Tests cover the cylindrical flank, both rounded caps, off-center curved cap distances, exact2m range, normalized directions, inside misses, depletion and malformed/truncated/trailing-byte sidecars. Render-triangle ray queries remain available separately.

The interaction call chain is `Action_Fell.UpdateOPTreeInfo` → `PEUtil.RayCastTree` → the active subterrain manager's layer-filtered `Physics.Raycast`. The camera ray starts at`mouseRay.origin−0.5×direction`, range100m, while the body ray starts at`player.position+up`, points forward, range2m; both must name the same tree. A host should use `ray_trunk` for these two queries. [RSubTerrainMgr.cs](<../../Assets/Scripts/ZhouXun/Random SubTerrain/RSubTerrainMgr.cs>) strips prototype MeshRenderer/MeshFilter, retains the collider, creates nearby clones with `TreeInfo.m_pos`, identity rotation and `(widthScale,heightScale,widthScale)`, puts them on NearTreeLayer21 and activates them. The inspected `UNITY_5` path preserves the nontrigger setting; only the older conditional branch changes colliders into triggers. Current `PeTree` has no source width/height fields, so unit scale remains an explicit sandbox assumption.

Player collision now uses the same source capsule through the headless cache described below. `ProjectSettings/TagManager.asset` names Player10, AIPlayer8 and NearTreePhysics21; the decoded PhysicsManager matrix enables both10↔21 and8↔21. Source movement obstruction masks also include NearTreePhysics (`Motion_Move_Human.cs` and `Motion_Move_Motor.cs`). The original interaction-only increment has been extended with analytic trunk solids for the sandbox movement/save-validation cache. Per-tree prototype indices and NaturalRes duration/yield rows remain unresolved; recovering an exact visual and collider does not establish those gameplay values.


### Analytic tree movement collision

[pe_tree_collision.c](../../rebuild/src/pe_tree_collision.c) contains a bounded, headless upright-capsule overlap and continuous sweep implementation. [export_tree_collision.py](../../rebuild/tools/export_tree_collision.py) invokes the same original-prefab decoder and mesh-identity checks as the visual exporter and writes [pe_tree_collider.h](../../rebuild/generated/pe_tree_collider.h). The header records the prefab hash, mesh GUID and collider component ID; its hexadecimal float literals retain the source binary32 values. Neither the collision runtime nor save validation loads Unity, raylib or external asset files. The renderer compares its PESC values against this generated definition, and exporter tests compare header/source/available PESC bytes.

For a player capsule of radius `r` and total height `h`, the exact Minkowski capsule in player-feet coordinates has center `tree.center−(0,h/2,0)`, half-axis `(tree.height/2−tree.radius)+(h/2−r)`, and radius `tree.radius+r`. The implementation solves the finite cylinder and exposed hemisphere entry roots analytically using double intermediates. Strict overlap excludes touching; sweeps suppress tangent/separating contact, preserve exact range-end contact, and return a surface normal toward the moving capsule. No leaf-card geometry or triangulated trunk approximation is involved.

`pe_sandbox_collision_update_with_trees` receives only live `PeTreeCapsule` values, copies them into the same transactional snapshot as terrain and construction, and compares all their fields independently of `PeWorld.revision`. Movement, support and overlap combine the earliest MC/Block45/furniture/bounds/tree result. Depletion removes the capsule on the next successful update; a tree-only change increments cache generation without rebuilding triangle BVHs. Invalid tree data preserves the previous complete snapshot. Tree extents may cross crop bounds or descend below terrain; world boundary planes remain a separate constraint.

The original `pe_sandbox_collision_update` API remains an explicit empty-tree wrapper. `overlap_geometry` and `sweep_geometry` include terrain, construction and world bounds but exclude trees. The camera uses the latter, preserving its existing tree-excluding policy. This is separate from Fell's tree-layer-only interaction rays: terrain and construction do not occlude those original layer21 queries.

Adventure gameplay supplies live capsules; legacy mode retains its earlier tree-free policy. Save version5 validates full tree collision. Version4 Adventure loading first validates its former geometry rules, then uses the separately tested, bounded same-height tree-escape migration before full validation. That recovery is compatibility policy, not a recovered Unity behavior; it must preserve an already-clear airborne state and never rewrite the input save or partially replace live state on failure. See the gameplay/save tests for the migration contract. Tree species selection, per-instance source width/height scaling and complete Unity motor physics remain unimplemented.

Headless validation passes strict C11 `-Werror`, ASan, UBSan and leak checks for exact touching, initial tangent/separating motion, high-speed sweeps, both rounded caps, off-axis cap normals, degenerate sphere axes, support, sliding, movement above the crown, snapshot ownership, tree movement/depletion with a reused world revision, geometry-only camera queries, rejected-update atomicity and colliders extending across crop boundaries. The mocked-GPU renderer suite also rejects a valid-shaped PESC with the wrong source radius. These tests establish geometry/data lifecycle; graphical movement verification is a separate host check.
