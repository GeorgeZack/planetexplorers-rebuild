## Save format

V20 preserves the literal v19 payload and appends32 bytes: machine identity(u32), item/count/instance(u32 each), durability(f32), running(u32), remaining ticks(u64 as low/high u32). Empty state requires all zero; an occupied job belongs only to entity20006 in a supported Adventure crop and owns exactly one qualified item with no bag/equipment/outfit/deployment/quickslot alias. Idle remaining ticks are0; running requires1..6000000 ticks and a damaged item; the currently bounded high word is0. Pre-v20 saves initialize an empty machine after their existing migrations; malformed v20 fails without replacing live game or transient owners. Never reconstruct the reserved item from a prototype, rerun material debit, or serialize modal/selection/GPU state. V19 preserves the v18 wire layout and appends26888 bytes (layout/count words plus1680 fixed16-byte item/count/instance/durability records). Adventure uses four420-cell source categories; Legacy/tutorial retain32 shared cells. The retained32-cell prefix is a compact projection of occupied Adventure cells, checked against the authoritative full suffix, not a downgrade promise. Validate pre-v19 flat saves before stable category migration; preserve exact identities, wear, quickslots and the counter. Use `pe_inventory_capacity` and category/transfer APIs for gameplay; `PE_INVENTORY_SLOTS` remains32 only for Legacy and old wire records. [Inventory contract](audit/SANDBOX_INVENTORY.md) owns split/exchange/merge/sort semantics. V18 retains the literal v17 payload and append648 bytes: installed/count words and32 fixed20-byte prototype/XYZ/depleted records. Unused records must be zero; pre-v18 saves infer no plant patch while retaining their trees. See [vegetation persistence](audit/SANDBOX_VEGETATION.md). V17 retains the literal v16 payload and appends100 bytes: count8 then eight stable-order(entity_id,balance,added) u32 triples. Wallet balances are nonnegative signed32, latch values0/1; non-Adventure balances/latches must be zero. Pre-v17 Adventure initializes archived purses/latches as an explicit migration, never inferred purchase history. See [wallet ownership](audit/TOWN_WALLETS.md). V16 retains the literal v15 payload and appends4 bytes for raw comfort, finite0..500. Versions1–15 default comfort to source500. Never persist derived stamina delay, buff phases or consumption timestamps. V15 retains the literal v14 payload and appends4 bytes for a shield instance reference, with the bag as sole item/durability owner. Pre-v15 saves infer no selected shield. Validate an exact Wood Shield34 bag instance, disallow primary/outfit/deployed aliases and retain exhausted instances with zero defense/protection. Normal shield use remains disabled until qualified presentation and block integration. V14 retains the literal v13 payload and append36 bytes for three fixed item-ID/instance-ID/durability clothing records. Validate old saves before initializing their previously visual Adventure outfits intact; this compatibility adapter advances the shared instance counter by3 and cannot reconstruct historical wear. V14 must never repair missing, broken or malformed clothing; Legacy records remain zero. V13 retains the literal v12 payload and append one four-byte float medpack cooldown, finite0..10; pre-v13 loads infer0. V12 retains the literal v11 payload with no appended bytes. The existing hunt state now includes4/5 for pending4105/4106 and6 for completed reporting; pre-v12 decoders reject those states. V11 retains the literal v10 payload and appends a32-bit hunt kill count. Pre-v11 defaults to0; none/travel require0, encounter state2 accepts0–3, states3–6 require4. Pre-v11 cannot contain return state3. Never serialize transient creature HP, threat, clocks or graphics state. V10 retains the literal v9 payload, then appends1812 bytes: hunt state and source XYZ, deployed count and64 fixed28-byte deployment records. Pre-v10 saves infer no hunt and no deployed objects. Preserve deployed instance identity/durability and reject inventory, equipment or quickslot aliases; unused records must be zero. The unchanged v7 prefix retains its depth64/128 layout; the retained v8 payload appends dimensions, a full payload for nonlegacy worlds, Annot completion and the original seventeen stable-order stock records. V9 appends medicine state, an explicit additional-stock count267 and those267 records. Pre-v9 saves infer no accepted medicine quest and uninitialized Annot stocks; pre-v8 saves also infer incomplete Annot and uninitialized starting stocks. Versions1–6 still load as depth64. See [route/save contract](audit/ADVENTURE_ROUTE.md). The retained welcome_page (0..9) persists acknowledged source replies; pages0..8 require no active Arrival/supplies state, and page9 enables the existing9031/9032 progression. Versions4/5 Adventure infer page9 to preserve their existing quests; Legacy infers0. Version 4 Adventure loads may use the bounded, geometry-swept tree-overlap migration; version 5 must already satisfy full collision validation. Versions 1–3 retain their Legacy migration. Do not generalize this compatibility relocation into ordinary movement, discard saved velocity/clocks, or commit a failed migration.

Older saves start at the prototype's 300, not starving; anything else fails without replacing the live game. The raw remainder, drain phase, condition timers and food cooldown are transient.
